## 2026-10-19 — Integration-02 выполнен (tasker)

- **Skills:** загружен `godot` — профильный стек: GDScript 4.4, `.tscn`-композиция/PackedScene-инстансы, CanvasLayer/Control, autoload/сигналы, GUT/headless, `--import`, portable-сборка через `GODOT_PATH`. Другие skills не требовались: задача не трогает БД/сеть/React/Docker/Python/Go.
- **Действие:** сборка готовых систем в играбельную сцену, без новой бизнес-логики. Связывание существующих API: `MainMenu`, `SceneRouter.bootstrap`, HUD T-19, DialogueScreen T-28, DeathHandler T-26, Campfire T-23, `BossArena` T-30/T-31/T-32, NPC T-28, ability gates/Journal (Integration-01).
- **Сцена-флоу:** `project.godot` `application/run/main_scene` → `res://ui/menus/MainMenu.tscn`. «Новая игра» (`_start_game(0)`) сбрасывает прогресс и меняет сцену на `Main.tscn`; `Main._ready` → `SceneRouter.bootstrap()` → зона 1 (+игрок); «Продолжить» грузит слот (`SaveManager.load_slot`) и стартует в зону из `respawn_zone_id`/метаданных слота; «Выход» — `get_tree().quit()`.
- **Монтаж `Main.tscn`:** HUD (T-19) вместо пустого слоя 10; `DialogueScreen` (T-28, слой 20, группа `dialogue_ui`); `DeathHandler` (T-26, группа `death_handler`); `Campfire` (T-23) помечен группой `campfire_ui`. DeathScreen (T-22), Inventory (T-21), Remap/Journal/Factions/FactionChoice (T-24), WorldMap (T-33) остаются в своих слоях.
- **Interact-система игрока:** новый `entities/player/player_interaction.gd` (`PlayerInteraction`) + узел `Interaction` в `Player.tscn`. По действию `interact` (`_unhandled_input`/`try_interact()`) выбирается ближайшая цель: `Bonfire` (радиус 24 px) → `Campfire.open(bonfire)`; `DialogueNpc`/`TraderNpc` (радиус `interaction_radius`, группа `dialogue_npcs`) → `DialogueScreen.open_npc(npc)`. `GameState.in_combat`, загрузка зоны (`SceneRouter.is_input_locked`) и уже открытый UI (`is_open()`) блокируют взаимодействие. `DialogueNpc._ready` добавляет NPC в группу `dialogue_npcs` (минимальная правка).
- **Арены боссов:** в зоны 1–4 добавлены `Arena` (Marker2D `ArenaAnchor`/`ArenaEntrance`) + инстансы `boss_arena_zone_01..04.tscn`. Арена стоит в комнате зоны (зоны однокомнатные 480×270, пол арены совпадает с полом зоны: y=224), `Trigger` сужен до правой половины (позиция 354,120; размер 228×200, вход с x=240), поэтому бой начинается при входе игрока в босс-половину, а не на спавне. `self_modulate.a = 0` у корня арены скрывает полноэкранную программную заглушку неба/пола, чтобы не закрывать арт зоны; босс — ребёнок арены — остаётся видимым; барьеры физические (группа `arena_barrier`). Зона 5 уже содержит свою арену T-32 (`Arena/BossSpawn` + `zone_05_arena.gd`), отдельной `boss_arena_zone_05.tscn` нет — не дублировалась.

- **Найденные/исправленные проблемы:**
  1. Зоны — одна комната 480×270, а арены — полноэкранные сцены: прямой инстанс закрывал арт зоны и триггерил бой на спавне. Решение — сузить `Trigger` до правой половины и скрыть только собственную отрисовку арены (`self_modulate.a = 0`), оставив детей (босса) видимыми.
  2. `BossArena` не выставлял `GameState.in_combat` (было только у арены 5) — interact/сохранение в бою на аренах 1–4 не блокировались; добавлено по существующим `fight_started`/`_on_boss_defeated`, с очисткой в `_exit_tree`.
  3. `-s`-режим (`--script`) компилирует скрипт до регистрации autoload-имён, поэтому `MainMenu`/HUD с `Config`/`GameState` не грузились из `SceneTree`-смоука — смоук переделан в обычную сцену-раннер.
  4. `root.add_child()` из `_ready` current_scene падал («Parent node is busy»), observer добавляется через `add_child.call_deferred`.
  5. `Trader`/`NPC_Keeper` уже заняты маркерами T-14 — NPC-узлы названы `KeeperNpc`/`TraderNpc`, маркеры сохранены (тесты T-14 и требование «на маркеры»).
