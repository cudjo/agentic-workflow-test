# SPEC — требования

> Владелец: **Analyst**. Выход шага анализа (дизайн-док §6.2). Информирует, не решает.
> Вход: `TICKET.md` + решения человека на гейте 1. Маршрут: `full` (UI-фича), режим приёмки — с QA.
> Статус: обновлён по решениям гейта 1 (гейт 1 повторно, решает человек).

## Цель

Дать пользователю защищённый веб-сервис, в котором он под своей учётной записью ведёт личные заметки с markdown-разметкой, тегами и поиском, просматривает их в виде плиток или списка и безопасно редактирует без потери данных.

## Сводка известного

**Известно (из TICKET.md):**
- CRUD заметок: создание, чтение, редактирование, удаление.
- Список заметок в двух видах: плитки (grid/карточки) и список (rows); переключение пользователем, выбранный вид сохраняется.
- Базовое форматирование текста (жирный, курсив, заголовки, списки и т.п.).
- Поддержка markdown: редактирование в markdown + превью (рендер).
- Full-stack: фронтенд + бэкенд, персистентность на сервере.

**Решения гейта 1 (v2, от человека):**
- **Мультиюзер + авторизация** (регистрация/вход/выход/сессия), доступ только к своим заметкам, серверная проверка владения.
- **Структура заметки расширена**: добавлены **теги**; появился **поиск по тексту и фильтрация по тегам** (комбинируемые).
- Остальное подтверждено без изменений: серверное хранение; live-сплит превью на широких + переключатель «Редактор/Просмотр» на узких; CRUD; переключение вида с сохранением в localStorage; markdown с санитизацией; лимиты длины; last-write-wins; удаление с подтверждением без корзины; явное сохранение + предупреждение при уходе.

**Вне рамок этой фичи (из запроса не следует):** коллаборация/совместное редактирование, шаринг заметок между пользователями, синхронизация между устройствами, мобильные нативные приложения, вложения/изображения, версионирование и история правок, экспорт/импорт, роли/администрирование.

## User Stories

### Аутентификация и доступ
- **US-1. Регистрация** — Как новый пользователь, я хочу зарегистрироваться, чтобы получить личный аккаунт и вести свои заметки.
- **US-2. Вход** — Как зарегистрированный пользователь, я хочу входить по своим учётным данным, чтобы получать доступ к своим заметкам.
- **US-3. Выход** — Как пользователь, я хочу выходить из аккаунта, чтобы завершить сессию и защитить данные.
- **US-4. Поддержание сессии** — Как пользователь, я хочу, чтобы сессия сохранялась между запросами (и разумно — между визитами), чтобы не входить каждый раз.
- **US-5. Приватность заметок** — Как пользователь, я хочу, чтобы мои заметки были доступны только мне.
- **US-6. Защита от несанкционированного доступа** — Как пользователь, я хочу, чтобы неавторизованный доступ перенаправлялся на вход, а не показывал данные.

### Заметки
- **US-7. Создание заметки** — Как пользователь, я хочу создавать новую заметку, чтобы сохранять свои мысли и текст.
- **US-8. Просмотр списка заметок** — Как пользователь, я хочу видеть список своих заметок, чтобы быстро находить нужную.
- **US-9. Переключение вида «плитки/список»** — Как пользователь, я хочу переключать отображение между плитками и списком.
- **US-10. Сохранение выбранного вида** — Как пользователь, я хочу, чтобы выбранный вид сохранялся между визитами.
- **US-11. Открытие и чтение заметки** — Как пользователь, я хочу открывать заметку и видеть отрендеренную markdown-разметку.
- **US-12. Редактирование в markdown** — Как пользователь, я хочу редактировать заметку в markdown с превью.
- **US-13. Базовое форматирование** — Как пользователь, я хочу применять базовое форматирование (жирный, курсив, заголовки, списки).
- **US-14. Удаление заметки** — Как пользователь, я хочу удалять ненужные заметки.
- **US-15. Защита от потери данных** — Как пользователь, я хочу, чтобы несохранённые правки не терялись случайно.

### Теги и поиск
- **US-16. Теги** — Как пользователь, я хочу назначать заметке теги, чтобы группировать их по темам.
- **US-17. Просмотр тегов** — Как пользователь, я хочу видеть теги на карточке/строке заметки.
- **US-18. Фильтрация по тегу** — Как пользователь, я хочу фильтровать заметки по тегу.
- **US-19. Поиск по тексту** — Как пользователь, я хочу искать заметки по тексту (заголовок + содержимое).
- **US-20. Комбинированный поиск/фильтр** — Как пользователь, я хочу сочетать поиск по тексту и фильтр по тегу.

## Acceptance Criteria (Given/When/Then)

### Аутентификация и доступ
- **AC-1 (Регистрация — успех)** — Given неавторизован, When ввожу валидные email/пароль и подтверждаю, Then создаётся аккаунт; я авторизован (или перехожу на вход — Q-A1), и мне доступны только мои (пустые) заметки.
- **AC-2 (Регистрация — дубликат)** — Given email занят, When регистрируюсь, Then отклонение с понятным сообщением; существующий аккаунт не затронут.
- **AC-3 (Регистрация — невалидные данные)** — Given неверный email/слабый пароль, When отправляю, Then конкретная ошибка валидации; аккаунт не создаётся.
- **AC-4 (Вход — успех)** — Given есть аккаунт, When ввожу корректные данные, Then авторизован и вижу свои заметки.
- **AC-5 (Вход — неверные данные)** — Given неверный пароль/несуществующий пользователь, When вхожу, Then обобщённое сообщение «неверные учётные данные» без раскрытия существования.
- **AC-6 (Rate limiting входа)** — Given серия неудачных попыток, When превышен порог, Then временная блокировка/замедление с сообщением (Q-A5).
- **AC-7 (Выход)** — Given авторизован, When «Выйти», Then сессия инвалидируется; защищённые запросы требуют вход заново.
- **AC-8 (Сессия между запросами)** — Given авторизован, When несколько защищённых запросов, Then остаюсь авторизованным.
- **AC-9 (Сессия — истечение)** — Given сессия истекла, When защищённый запрос, Then 401/redirect на login, не данные.
- **AC-10 (Неавторизованный доступ)** — Given неавторизован, When открываю страницу/API, Then redirect на login (браузер) или 401 (API); заметки не показываются.
- **AC-11 (Ownership — чтение чужой)** — Given авторизован A и есть заметка B, When A обращается по id, Then доступ запрещён (403/404 — Q-A7), данные B не раскрываются.
- **AC-12 (Ownership — изменение чужой)** — Given заметка B, When A редактирует/удаляет через API, Then операция отклоняется, заметка B не меняется.
- **AC-13 (Ownership — список)** — Given авторизован A, When запрашиваю список, Then только заметки A.
- **AC-14 (Ownership — на сервере)** — Given попытка обойти UI, When запрашиваю чужой ресурс через API, Then серверная проверка отклоняет.
- **AC-15 (CSRF)** — Given активная сессия, When межсайтовый state-changing запрос без валидного токена, Then отклоняется (Q-A6).

### CRUD заметок
- **AC-16** — Given список, When «Создать» + заголовок/текст, Then заметка создаётся и отображается первой.
- **AC-17** — Given пустая заметка, When сохраняю, Then запрет с сообщением.
- **AC-18** — Given есть заметки, When кликаю, Then открывается с сохранённым содержимым.
- **AC-19** — Given открыта заметка, When меняю и сохраняю, Then изменения персистентны на сервере.
- **AC-20** — Given несохранённые изменения, When закрываю/переключаю/ухожу, Then предупреждение сохранить/отказаться.
- **AC-21** — Given заметка, When удаляю, Then подтверждение; при подтверждении исчезает и не возвращается после перезагрузки.
- **AC-22** — Given инициировал удаление, When отказываюсь, Then остаётся без изменений.
- **AC-23** — Given нет заметок, When открываю, Then empty-state с CTA «Создать заметку».

### Переключение вида плитки/список
- **AC-24** — Given список, When «плитки», Then карточки сеткой; When «список», Then строки.
- **AC-25** — Given выбрал вид, When перезагружаю, Then сохраняется (localStorage; дефолт — Q5a).
- **AC-26** — Given одни заметки, When переключаю вид, Then состав/содержимое/порядок неизменны.
- **AC-27** — Given первый визит, When открываю, Then вид по умолчанию (дефолт: плитки).

### Markdown-редактирование и превью
- **AC-28** — Given открыта заметка, When ввожу markdown, Then текст сохраняется как raw markdown.
- **AC-29** — Given валидный markdown, When превью, Then форматированный HTML.
- **AC-30** — Given редактирую, When смотрю, Then live-сплит на широких, переключатель на узких.
- **AC-31** — Given сохранил markdown, When открываю в просмотре, Then рендер соответствует.
- **AC-32** — Given редактирую, When форматирую, Then заголовки/жирный/курсив/списки/код рендерятся; toolbar опционален (Q3).

### Теги
- **AC-33** — Given создаю заметку, When добавляю теги, Then сохраняются и доступны после перезагрузки.
- **AC-34** — Given открыта заметка с тегами, When меняю теги и сохраняю, Then набор обновляется персистентно.
- **AC-35** — Given у заметки есть теги, When смотрю список, Then теги видны на карточке и в строке.
- **AC-36** — Given только пробелы/пустой тег, When сохраняю, Then пустой тег не добавляется.
- **AC-37** — Given дублирующийся тег, When сохраняю, Then дубликат не создаётся.
- **AC-38** — Given длинный/спецсимвольный тег, When отображается, Then не ломает верстку, рендерится корректно.

### Поиск и фильтрация
- **AC-39** — Given есть заметки, When ввожу запрос, Then совпадения по заголовку/содержимому (Q-S1).
- **AC-40** — Given заметки с тегами, When выбираю тег, Then только заметки с этим тегом.
- **AC-41** — Given активны поиск и фильтр, When применяю оба, Then удовлетворяющие обоим условиям.
- **AC-42** — Given нет совпадений, When смотрю, Then empty-state «ничего не найдено» + сброс.
- **AC-43** — Given активен поиск/фильтр, When сбрасываю, Then все заметки пользователя.
- **AC-44** — Given несколько пользователей, When A ищет, Then только заметки A.

### Безопасность рендера
- **AC-45** — Given markdown с сырым HTML/опасным кодом, When отображается, Then не исполняется (санитизация).
- **AC-46** — Given `<b>текст</b>` как текст, When превью, Then детерминировано (allowlist).
- **AC-47** — Given тег с HTML-подобными символами, When отображается, Then как текст, без инъекции.

## Нефункциональные требования

**Производительность**
- **NFR-1** — Отклик списка на ~200–500 заметках до 1 c.
- **NFR-2** — Ввод текста без задержек (debounce).
- **NFR-3** — Первая загрузка ~2–3 c.
- **NFR-4** — Поиск/фильтр по сотням заметок ~1 c (серверный, debounce).

**Безопасность**
- **NFR-5** — Markdown/HTML санитизируется, XSS не исполняется.
- **NFR-6** — Серверная проверка владения на каждой операции (read/update/delete/list/search/filter).
- **NFR-7** — Валидация/санитизация на сервере.
- **NFR-8** — Секреты не в клиенте/репозитории.
- **NFR-9** — Пароли только хешем (bcrypt/argon2); не логируются, не в ответах.
- **NFR-10** — Cookie: HttpOnly, Secure, SameSite; инвалидация при logout.
- **NFR-11** — CSRF-защита state-changing запросов.
- **NFR-12** — Rate limiting входа/регистрации.
- **NFR-13** — Единый код отказа без утечки существования (Q-A7).
- **NFR-14** — Теги рендерятся как текст.

**Доступность (a11y)**
- **NFR-15** — Управление с клавиатуры (auth-формы, CRUD, переключатель вида, поиск, теги).
- **NFR-16** — Переключатель вида и поиск/фильтр: корректная семантика и имена.
- **NFR-17** — Иконки/кнопки без текста: aria-label.
- **NFR-18** — Контраст WCAG AA, фокус видим.
- **NFR-19** — Ошибки форм объявляются скринридеру, связаны с полями.
- **NFR-20** — Результаты поиска/empty-state читаются скринридером.

**Отзывчивость / адаптивность**
- **NFR-21** — Адаптив: десктоп/планшет/мобильный.
- **NFR-22** — Плитки перестраиваются; список читаем на узких.
- **NFR-23** — На узких сплит → переключатель «Редактор/Просмотр».
- **NFR-24** — Формы входа/регистрации, поиск/теги адаптивны.

**Надёжность / данные**
- **NFR-25** — Персистентность; перезапуск не теряет данные.
- **NFR-26** — Запись атомарна.
- **NFR-27** — Связь заметка↔теги консистентна.

**Проверяемость**
- **NFR-28** — E2E как пользователь: регистрация → вход → заметка с тегами → поиск/фильтр → переключение видов → markdown-превью → редактирование → удаление → выход; плюс изоляция между пользователями.

## Открытые вопросы (для человека на гейте 1)

### Решено на гейте 1
- **Q1. Модель пользователей** — Мультиюзер + авторизация.
- **Q2. Структура заметки** — Заголовок(опц.) + markdown + теги + createdAt/updatedAt; pin вне MVP.
- **Q6. Поиск/фильтрация** — Поиск по тексту + фильтр по тегам, комбинируемые.
- **Q4. Форма превью** — live-сплит / переключатель.
- **Q5. Сохранение вида** — localStorage; дефолт плитки.
- **Q8. Конкурентность** — last-write-wins.
- **Q9. Потеря данных** — явное сохранение + предупреждение.
- **Q10. Удаление** — с подтверждением, без корзины.
- **Q11. Политика markdown/HTML** — санитизация, allowlist.
- **Q12. Хранение** — серверная персистентность.

### Осталось открытым (с дефолт-предположениями)
- **Q3. Toolbar форматирования** — дефолт: markdown-синтаксис обязателен, toolbar — nice-to-have.
- **Q5a. Дефолтный вид** — дефолт: плитки.
- **Q7. Лимиты объёма** — дефолт: заголовок ≤ 200, текст ≤ 100 000 симв.
- **Q13. Локализация** — дефолт: один язык интерфейса (уточнить).
- **Q-A1. Модель регистрации** — дефолт: открытая саморегистрация, сразу авторизован.
- **Q-A2. Идентификатор/пароль** — дефолт: вход по email; мин. пароль 8 симв.
- **Q-A3. Сессии** — дефолт: ~7 дней с refresh; несколько сессий разрешены.
