Редактировать

Индексы ускоряют чтение и замедляют запись — всегда есть цена. Ниже — рабочий конспект.

Когда какой индекс

  1. B-tree — сравнения =, <, >, сортировка, LIKE 'abc%'
  2. GIN — массивы, jsonb, полнотекстовый поиск
  3. BRIN — большие таблицы с естественным порядком (логи, время)

Как проверять

Не верить интуиции, а смотреть план запроса:

EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM notes
WHERE user_id = 42
ORDER BY updated_at DESC;
Seq Scan на 200 строках — это нормально. Важно понимать, где он уже не нормально.

К моим заметкам

Безопасность рендера: как показывается «опасный» ввод

Ниже — то же превью, в которое пользователь вставил сырой HTML. В продукте такой ввод попадает в allowlist-санитайзер: теги, которых нет в списке, не исполняются, а показываются как текст (AC-45…AC-47, NFR-5, NFR-14).

Привет, жирный разрешён, а вот это — не исполняется:

<script>alert('xss')</script>

<img src=x onerror=alert(1)>

<b>текст в b-теге</b>

скрипт вырезан обработчик события вырезан элемент вне allowlist → как текст strong / em / code / ul / ol / pre / blockquote / table — разрешены
Что утверждается на этом экране
  • Один h1 на страницу: заголовок заметки. Заголовки внутри markdown начинаются с h2 — иначе структура ломается для скринридеров и SEO.
  • Теги над текстом, даты и размер — в мете. Действия «Редактировать» (primary) и «Удалить» (тихая опасная кнопка) справа.
  • Удаление — только через подтверждение (AC-21/22). После удаления открытой заметки возвращаемся к списку (E13).
  • Ширина текста ограничена ~72 символами для читаемости; таблицы и длинный код получают горизонтальный скролл (E4, E7).
  • Чужая заметка отдаётся как «не найдена» — без подтверждения существования (AC-11, Q-A7 → 404).
  • Открытый вопрос: показывать ли «исправлена через N минут после создания» и нужна ли кнопка «Поделиться» — вне MVP.
